# إدارة اللجان والطلاب — PWA مجانية 100%

نظام إدارة اللجان والطلاب والطلبات والمالية: واجهة React منشورة على GitHub Pages، وخلفية Firebase بخطة Spark المجانية فقط. لا Cloud Functions ولا Cloud Storage ولا إشعارات Push — كل المنطق في التطبيق، والسلطة النهائية في قواعد أمان Firestore مع دفعات ذرية.

## المزايا

- تسجيل بالهاتف وكلمة مرور (بريد وهمي حتمي `p.<رقم>@system.app` لا يُخزن في قاعدة البيانات)، ومراجعة إدارية لكل حساب جديد تصل كرسالة داخل التطبيق.
- لجان بألوان معتمدة وصلاحيات دقيقة لكل عضو (منح/منع فردي + صلاحيات عامة للجنة).
- قالب طلاب ديناميكي، بحث عربي مطبّع، فلاتر، أرشفة، استيراد وتصدير Excel، ونسخة احتياطية متعددة الأوراق.
- طلبات بتوجيه إلزامي (وجهة ثابتة أو اختيار المرسل) مع حالات: مُرسل ← قيد المراجعة ← مقبول/مرفوض ← منفَّذ، وسجل مالي غير قابل للتعديل يُنشأ بنفس الدفعة الذرية.
- إعلانات ودردشة نصية بين لجان يحددها المدير، مع إيصالات قراءة بعلامة «جديد».
- ثيم فاتح/داكن، أحجام خط، ولون رئيسي — إعدادات شخصية محفوظة محليًا.
- PWA قابلة للتثبيت مع تخزين ملفات التطبيق فقط (لا تُخزن بيانات Firestore أو المالية).

## المتطلبات

- Node.js 20+
- حساب Firebase مجاني (خطة Spark)
- لمحاكي قواعد Firestore في الاختبارات: Java 17+

## الإعداد المحلي

```bash
npm install
cp .env.example .env   # ثم ضع قيم مشروعك من Firebase Console
npm run dev
```

## إعداد Firebase

1. أنشئ مشروعًا في [Firebase Console](https://console.firebase.google.com) وأضف تطبيق ويب، ثم انسخ الإعدادات إلى `.env`.
2. من **Authentication → Sign-in method** فعّل **Email/Password**.
3. أنشئ Firestore Database (وضع الإنتاج).
4. **إنشاء المدير الأعلى الأول (يدوي فقط):** من Firestore أنشئ وثيقة `users/<uid المستخدم>` بالحقول:

   | الحقل | القيمة |
   |---|---|
   | `uid` | نفس uid الحساب من Authentication |
   | `name` | اسم المدير (حرفان فأكثر) |
   | `phone` | رقم دولي بأرقام فقط، مثال `963900000000` |
   | `status` | `approved` |
   | `role` | `superAdmin` |
   | `globalPermissions` | `[]` |
   | `committeeIds` | `[]` |
   | `createdAt` | طابع زمني (timestamp) |

   لا يمكن منح دور `superAdmin` من داخل التطبيق أبدًا؛ من بعده يستطيع المدير الأعلى قبول الحسابات الجديدة وتعيين الأدوار.

5. انشر القواعد والفهارس من جهازك:

```bash
npm i -g firebase-tools
firebase login
firebase use <معرف-المشروع>
firebase deploy --only firestore:rules,firestore:indexes
```

## النشر على GitHub Pages

1. أنشئ مستودعًا عامًا باسم `student-app` (فارغًا بلا README) ثم ارفعه:

   ```bash
   git remote add origin https://github.com/<username>/student-app.git
   git push -u origin main
   ```

2. من إعدادات المستودع: **Settings → Secrets and variables → Actions → Variables** أضف القيم الأربع:
   `VITE_FIREBASE_API_KEY` و`VITE_FIREBASE_AUTH_DOMAIN` و`VITE_FIREBASE_PROJECT_ID` و`VITE_FIREBASE_APP_ID`.
   بدونها يبنى الموقع ويعرض شاشة «إعداد مطلوب». (هذه القيم عامة بطبيعتها؛ الحماية في Auth والقواعد.)
3. من إعدادات المستودع: **Settings → Pages → Source: GitHub Actions**.
4. سير العمل `deploy-pages.yml` يبني وينشر تلقائيًا عند كل دفع إلى `main`، ويحسب مسار القاعدة من اسم المستودع (`/student-app/`). المسارات داخل التطبيق hash-based فلا تظهر أخطاء 404 عند التحديث.

## الاختبارات

```bash
npm run typecheck   # فحص الأنواع
npm run lint        # ESLint
npm test            # اختبارات الوحدة (vitest)
npm run test:rules  # قواعد Firestore على المحاكي (يتطلب Java)
npm run icons       # إعادة توليد أيقونات PWA في public/icons
```

اختبارات القواعد تغطي: منع غير المقبولين، ربط التسجيل برسالة الإدارة الذرية، منع التصعيد الذاتي، حصر الألوان باللوحة المعتمدة، تزامن العضوية مع ملف المستخدم، صرامة القالب على الطلاب، توجيه الطلبات، وذرية التنفيذ المالي مع الحركة غير القابلة للتعديل، وقواعد القنوات والإخفاء الإداري.

## حدود النسخة المجانية (مقصودة)

- لا استعادة ذاتية لكلمة مرور منسية (البريد وهمي) — يعيد المدير ضبطها أو ينشئ حسابًا جديدًا.
- لا إشعارات عند إغلاق التطبيق؛ رسائل الموافقات والشات داخل التطبيق فقط.
- الشات نصي بلا مرفقات (لا Cloud Storage).
- حذف حساب Auth لمستخدم آخر أو حذف بيانات نهائي يتم يدويًا من Firebase Console.
- راقب حصص قراءات/كتابات Spark؛ عند نفادها تتوقف الخدمة مؤقتًا دون فوترة.
